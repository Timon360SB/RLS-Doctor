# Пример приложения со списком задач

[English](README.md)

Небольшое Node-приложение читает тестовые задачи из собственной схемы
`task_board`. Оно использует настоящий `supabase-js` и **SDK, установленный из
собранного архива**. Затем **CLI, установленный из wheel**, проверяет отдельный
явно заданный сценарий. Исходники SDK напрямую не импортируются, таблицы
прежнего демо не используются. Веб-интерфейса в этом примере нет.

Это наш синтетический пример интеграции, а не независимое пользовательское
приложение. Доверенный пробник роли устанавливается явно миграцией примера;
команды диагностики не добавляют его в чужие приложения.

## 1. Запуск

Откройте Docker Desktop и дождитесь работающего Linux-движка. Нужны Node.js
22.12+/24, pnpm 11.25.0 и uv. В PowerShell из корня репозитория выполните:

```powershell
pnpm.cmd install --frozen-lockfile
uv sync --project python --frozen --group dev
uv run --project python python scripts/task_board_check.py --check
```

Первые две команды готовят зависимости репозитория. `--check` явно разрешает
подготовку только этого примера: запуск отдельной базы, создание двух тестовых
Auth-пользователей и назначение им трёх тестовых задач. При первом запуске
могут загружаться Docker-образы и закреплённые зависимости приложения.
Ключи, пароли, строки таблицы и сырые ошибки не выводятся и не записываются
проверяющим скриптом. Копировать переменные окружения не требуется.

| Что | Значение |
| --- | --- |
| Проект Docker | `rls-doctor-task-board` |
| API | `http://127.0.0.1:56321` |
| PostgreSQL | `127.0.0.1:56322` |
| Таблица | `task_board.tasks` |
| Файлы и отчёты | `.rls-doctor/task-board/`, исключено из Git |
| Собранные архивы | `.rls-doctor/distribution-check-…/`, исключено из Git |

Прежнее демо использует 54321/54322, учебная лаборатория — 55321/55322.
Они остаются отдельными средами. Блокировка ОС защищает от двух одновременных
проверок этого примера. Изменённые файлы подготовки сохраняются: вместо
перезаписи или сброса базы возвращается SAMPLE_FILES_CHANGED.

Supabase/Docker может публиковать порты на всех интерфейсах компьютера.
Loopback-ограничение исходящих запросов не ограничивает входящие подключения;
используйте доверенную среду разработки. См. [ограничения](../../docs/limitations.md).

## 2. Что должно произойти

1. Соберутся и проверятся архивы SDK/Python: состав, лицензии, схема событий,
   установка, типы SDK, запись события и чтение установленным CLI.
2. В отдельную папку установятся закреплённые зависимости приложения и новый
   архив SDK. Публикации в npm/PyPI не происходит.
3. Будут созданы два тестовых пользователя. Алисе назначаются две задачи,
   Бобу — одна. Подготовка обновляет только три известных тестовых ID.
4. Приложение выполнит настоящие запросы от Алисы, Боба и анонимного клиента.
   Оно проверяет точный состав записей и сохраняет очищенное событие SDK.
5. Установленный CLI проверит событие и выполнит отдельный локальный сценарий:
   HTTP, число строк, наличие своих и отсутствие чужих задач, роль сервера,
   чтение каталогов настоящей `task_board.tasks` и включённый RLS.

| Сценарий | Ожидается |
| --- | --- |
| Алиса | PASS, HTTP 200, две свои задачи; задача Боба отсутствует |
| Боб | PASS, HTTP 200, одна своя задача; обе задачи Алисы отсутствуют |
| Анонимный клиент | PASS, HTTP 200, ноль задач; все три записи отсутствуют |

Пробник роли находится в `public`, таблица — в `task_board`. Этот прогон
проверяет их взаимодействие на настоящем API. Обезличенное событие v1 содержит
имя ресурса, но не полный исходный запрос: схема, фильтры и тестовые значения
задаются отдельно в сценарии. Подтверждённая роль относится к локальному
воспроизведению, а не к личности исходного клиента.

Ожидаются три строки PASS с ожидаемым/полученным количеством задач и код 0.
В конце появится путь к папке запуска. В ней лежат `summary.json`, а внутри
`alice`, `bob`, `anonymous` — `event.json`, `tasks.yaml`, `report.json` и файл
захвата. Для разбора используйте эти очищенные файлы; не сохраняйте сырой
`supabase status` и не пересылайте секреты.

## 3. Где посмотреть подключение SDK

В `app.mjs` задаётся `db.schema`, обёртка `createCaptureFetch` передаётся как
`global.fetch`, хранение сессии и обновление токенов отключены. Перед выходом
пример дожидается записи события. Ответ читает само приложение; SDK обязан
оставить его пригодным для чтения. Учётные данные передаются только в памяти
из явно разрешённого проверяющего скрипта.

SQL в `supabase/migrations/` и `seed.sql` — отдельная подготовка одноразового
приложения. Команды doctor/inspect/session/replay не применяют эти миграции
к пользовательским базам.

## 4. Остановка

```powershell
uv run --project python python scripts/task_board_check.py --stop
```

Останавливается только этот пример, данные сохраняются. Повторный `--check`
создаст новую пару пользователей и переназначит ей три тестовые задачи.
Старые Auth-пользователи остаются до явного удаления или сброса этой среды.
Автоматического сброса, удаления данных или изменений других баз нет.

Сценарий добавлен в local-integration CI. Успешный локальный запуск не заменяет
свежий GitHub Actions, независимое ревью или установку на чистой Windows.
