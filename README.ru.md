## Начать работу

Установите [uv](https://docs.astral.sh/uv/getting-started/installation/) и скачайте
этот репозиторий архивом ZIP либо через Git. Подготовьте адрес, порт, пользователя
и пароль подключения из настроек своего PostgreSQL/Supabase-провайдера.

**Windows:** откройте PowerShell в папке репозитория и выполните:

```powershell
.\rls-doctor.cmd
```

Запускатель при необходимости подготовит Python 3.12 и закреплённые зависимости,
затем откроет помощник подключения. Отдельная команда установки зависимостей не нужна.
Для первой загрузки требуется интернет. Системные программы автоматически не
устанавливаются, права администратора не нужны. Если uv отсутствует, появится ссылка на установку.

**macOS / Linux либо обычный терминал с uv:**

```sh
uv run --project python --python 3.12 --frozen --no-dev rls-doctor start
```

1. Введите адрес сервера и разрешите чтение только служебных каталогов прав.
2. Заполните отдельные поля подключения. Пароль вводится скрыто; для удалённого сервера обязателен проверяемый TLS.
3. Выберите существующую таблицу и роль базы данных, доступ которой нужно разобрать.
4. Прочитайте первый отчёт. Через меню проверяйте другие таблицы, смотрите обзор
   схемы, сохраняйте JSON и переключайте язык EN/RU.

При следующем запуске используется профиль без секретов. Разрешение и пароль
запрашиваются один раз, когда выбранному действию нужно подключение; следующие
действия используют эту сессию. После закрытия ссылки на данные подключения
отпускаются; пароль и полная строка подключения не записываются. Пункт **6**
забывает данные сессии и позволяет переподключиться. Это не обещание гарантированного
стирания памяти. Заданные вами переменные окружения остаются под вашим управлением.

**Docker, Node.js, тестовая база и YAML для этого пути не нужны.**
Поддерживаются PostgreSQL 16, 17 и 18.

Запуск сразу на русском: `.\rls-doctor.cmd start --language ru`. В открытом меню
язык можно поменять в любой момент. [Подробное подключение](docs/existing-database.ru.md):
TLS, ограниченные права и готовые строки подключения.

### Установить CLI для запуска из любой папки

Необязательно: из папки репозитория установите локальный Python-пакет в отдельное окружение uv:

```powershell
uv tool install --python 3.12 .\python
uv tool update-shell
```

Переоткройте терминал, перейдите в папку своего приложения и выполните `rls-doctor start`.
Профиль и явно сохранённые отчёты относятся к этой рабочей папке. Устанавливается
локальная версия исходников; после изменений переустановите её командой
`uv tool install --force --python 3.12 .\python`. Удаление: `uv tool uninstall rls-doctor`.
Запускатель репозитория использует lockfile, установка инструмента — закреплённые
зависимости Python-пакета. Установку из публичного реестра пока не обещаем.

## Возможности

| Возможность | Практическая польза |
| --- | --- |
| Подключение по шагам и профиль | Первый отчёт без составления DSN, копирования переменных окружения и подготовки фикстур |
| Диагностика таблицы и роли | USAGE схемы, SELECT таблицы/столбцов, членство ролей, владелец/BYPASSRLS, RLS/FORCE и применимые политики |
| Обзор схемы | До 30 таблиц по умолчанию, максимум 50; препятствия доступа и спорные настройки первыми, в одном снимке каталогов |
| Ограниченный разбор условий | Постоянные true/false и поддерживаемое точное равенство auth.uid/столбца; остальные условия остаются неизвестными |
| Последовательное расследование | Права и default-deny отдельно от авторизации, условий владельца, наличия строк и фильтров |
| Понятные ошибки | Безопасный SQLSTATE, этап подключения/чтения каталогов и дальнейшее действие EN/RU; неизвестная причина обозначается явно |
| Консоль и JSON | Читаемые выводы, ID диагностики, время UTC и экспорт без перезаписи существующих файлов |
| Необязательный Node.js SDK | Явная запись метаданных поддерживаемых REST GET, привязка к проекту и отдельная проверка Auth |
| Необязательные локальные сценарии | Сравнение синтетических GET-ожиданий с результатом в явно разрешённом одноразовом стенде |

## Как понимать результат

| Результат | Значение |
| --- | --- |
| Препятствие доступа / BLOCKED | Каталоги подтверждают базовое препятствие GRANT, USAGE схемы или default-deny для выбранной роли |
| Требует проверки / REVIEW | RLS выключен/обходится либо SELECT выдан только на столбцы; проверьте, соответствует ли это замыслу |
| Базовых препятствий нет / NO_BASIC_BLOCKER | Основные проверки не нашли препятствия; корректность политик и видимость строк не доказаны |
| UNKNOWN | Данных недостаточно для подтверждения поведения запроса или его исходной причины |
| ERROR | Операция не завершилась; выполните указанное следующее действие |

UNKNOWN в отчёте каталогов не мешает показать конкретное найденное препятствие.
HTTP 200 с пустым массивом не доказывает запрет RLS. Выбранная роль, сохранённое
событие и успешная проверка Auth не подтверждают роль PostgreSQL исходного запроса.

Коды разовых проверок: **0 PASS, 1 FAIL, 2 UNKNOWN, 3 ERROR**. Команда `connect`
возвращает 0 при сохранении профиля, закрытие меню — 0 при завершении сессии.
Это не подтверждение доступа к строкам. `start --once` сохраняет UNKNOWN / код 2.

### Прямые команды

В репозитории вместо `rls-doctor` используйте `.\rls-doctor.cmd` либо префикс
`uv run --project python rls-doctor`:

```powershell
rls-doctor start
rls-doctor connect --connection-string
rls-doctor diagnose --guide
rls-doctor overview --schema public --role authenticated --limit 30
rls-doctor diagnose public.orders --profile .rls-doctor/project.json --language ru
```

По умолчанию `overview` берёт схему и роль из профиля. Лимит применяется по имени
таблиц до сортировки проблем; неполнота явно отмечается. У каждого запроса есть
фиксированные лимиты времени/блокировки, между таблицами проверяется бюджет 30 секунд.
Представления и необычные имена пропускаются; условия политик не исполняются.
Для JSON-автоматизации задайте соответствующую профилю DSN приватно и используйте
`--approve-read-only --format json`, при необходимости `--output НОВЫЙ_ФАЙЛ.json`.

## Приватность и ограничения

- Диагностика каталогов не читает строки приложения и не меняет пользователей, политики, права или данные.
- Полные DSN, пароли, токены, сырые ошибки сервера, SQL политик и тела запросов/ответов не выгружаются.
- В профиле есть метаданные подключения, в отчёте — имена объектов каталогов; проверяйте отчёт перед передачей.
- Удалённое подключение требует проверки сертификата и имени; перенаправления и настройки провайдера контролирует оператор.
- Произвольные функции, сложные политики, view, точки входа через секции и видимость строк требуют отдельной проверки.
- Браузерный перехват, запись в БД, автоматические исправления, удалённый replay и веб-панель не входят в этот MVP.

## Необязательные SDK и примеры

Node.js 22.12+ нужен только для SDK. Обёртка сохраняет исходное поведение fetch/Response
и отделяет ошибки диагностики. Запись и проверка Auth включаются явно.
[API SDK](packages/capture-sdk/README.md) и [привязка запроса](docs/existing-database.ru.md#добавить-запрос-приложения).

Для знакомства с синтетическими примерами есть `.\lab.cmd` и `.\lab.cmd -Language ru`.
Эта отдельная лаборатория разработчика требует Linux-движок Docker, Node.js, закреплённую
pnpm и uv; запускатель готовит локальный Supabase. Для собственной базы она не нужна.
[Руководство проверки](docs/practice-testing.ru.md) объясняет 18 пунктов и ожидаемые ошибки.
[Приложение с задачами](examples/task-board/README.ru.md) проверяет установленные пакеты,
двух владельцев и анонимный доступ. Наш пример не подтверждает независимое внедрение.

## Разработка и готовность к выпуску

Локальная проверка включает тесты Python, приватности и контракта, реальные
PostgreSQL 16/17/18, изолированный TLS-стенд с ограниченной ролью, локальный
Supabase SDK/Auth и установленные пакеты Python/SDK. Текущим изменениям ещё нужны
соответствующий прогон CI, установка на чистой машине и независимое воспроизведение
вторым разработчиком перед публичным выпуском. Внешний облачный проект пользователя
не проверялся. Общая защищённость приложения этими проверками не удостоверяется.
