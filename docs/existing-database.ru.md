# Диагностика существующей базы

[English](existing-database.md)

Для диагностики своей PostgreSQL/Supabase-базы нужны Python и uv. Docker, Node.js,
тестовые пользователи и YAML-сценарии не требуются. Node.js нужен только если вы
дополнительно подключаете SDK к своему приложению.

## Первое подключение

В копии репозитория выполните:

```powershell
uv sync --project python --frozen
uv run --project python rls-doctor connect --language ru
```

1. Укажите имя сервера или IP своей базы.
2. Подтвердите чтение каталогов на этом сервере.
3. В скрытое поле вставьте строку подключения PostgreSQL. Это не API-ключ Supabase.
4. Выберите таблицу и роль по номерам. Читаются только каталоги, строки не загружаются.
5. При необходимости укажите адрес Supabase API, например `https://YOUR_PROJECT.supabase.co`.
   Нужен только адрес, без пути, ключей и параметров. Он связывает будущие события с профилем.
6. Получите первичный отчёт и профиль `.rls-doctor/project.json`.

Профиль содержит адрес, порт, имя базы, пользователя, таблицу, роль, TLS-настройки,
путь CA и случайный ID проекта. Пароль, DSN и токены в нём отсутствуют. Профиль по
умолчанию находится в игнорируемом Git рабочем каталоге. Другой путь:
`connect --profile PATH_TO_NEW_PROFILE.json`. Существующий файл не перезаписывается.
Успешная настройка профиля возвращает код 0; видимость строк в отчёте остаётся UNKNOWN.

## Повторная проверка

```powershell
uv run --project python rls-doctor diagnose --language ru
```

Команда использует сохранённый профиль, запрашивает разрешение и скрыто вводит
только пароль. Полную строку подключения копировать заново не нужно. Для другого
профиля: `diagnose --profile PATH_TO_PROFILE.json`.

Для автоматизации задайте `RLS_DOCTOR_DATABASE_URL` приватно через окружение или
менеджер секретов и используйте `--approve-read-only --format json`. В JSON-режиме
вопросов нет. Host, порт, база и пользователь DSN должны соответствовать профилю.
Пароли нельзя передавать в аргументах команд, Git, отчётах или чате.

Без профиля доступен точечный запуск с прежним интерфейсом:

```powershell
uv run --project python rls-doctor diagnose public.orders --host YOUR_DATABASE_HOST --role authenticated --language ru
```

Он попросит скрыто ввести DSN. Другую переменную окружения можно выбрать через
`--connection-env NAME` при запуске без профиля; в профиле задаётся её имя.

## Пошаговое расследование

```powershell
uv run --project python rls-doctor diagnose --guide --language ru
```

Отчёт разделяет проблемы GRANT/default-deny, применимость RLS, авторизацию,
формы условий политик и неопределённость строк. Режим guide дополнительно задаёт
вопросы о том, проверены ли наличие нужной строки, фактические фильтры и роль.
Ответы — только да/нет/неизвестно; значения строк, SQL и токены не запрашиваются.
Ответы оператора остаются UNVERIFIED и не превращаются в доказанную причину.

Внутри сервера распознаются постоянные условия true/false и точное сравнение
`auth.uid()` со столбцом, включая простую форму `(select auth.uid())`. Учитывается
разница между OR разрешающих и AND ограничивающих политик. Текст SQL и литералы
не выгружаются, функции политик не выполняются. Сложные выражения, приведения,
неподдержанные типы и скрытые зависимости остаются нераспознанными. Анализ USING
и WITH CHECK структурный; это не обещание воспроизвести произвольную политику.

## Добавить запрос приложения

В настройках SDK используйте `projectId` и `allowedOrigin`, выданные connect:

```typescript
import { createCaptureFetch, createJsonFileSink } from '@rls-doctor/capture-sdk';

const captureFetch = createCaptureFetch(fetch, {
  enabled: true,
  projectId: 'UUID_FROM_CONNECT',
  allowedOrigin: 'https://YOUR_PROJECT.supabase.co',
  resources: ['orders'],
  verifyAuth: true,
  sink: createJsonFileSink({ directory: '.rls-doctor/captures' }),
});
// Передайте captureFetch в global.fetch вашего Supabase-клиента.
```

Событие 1.1 содержит ID проекта, SHA-256 только адреса API (не токена), схему
Accept-Profile и имена явно выбранных простых столбцов. Значения фильтров и строки
не записываются. Сложная проекция обозначается как неизвестная. Если projectId
не указан, SDK по-прежнему создаёт совместимое событие 1.0.

`verifyAuth` по умолчанию выключен. Явное включение разрешает дополнительный GET
`/auth/v1/user` на тот же адрес с заголовками этого запроса. Перенаправления
запрещены, время ограничено 3 секундами, размер Auth-ответа — 32 КиБ. Данные Auth
проверяются только в памяти; в событие попадает состояние проверки без ID, email
или токенов. Исходный запрос/Promise/Response сохраняются, его тело SDK не читает.
Проверка не задерживает возврат ответа приложению; запись события может завершиться позже.

```powershell
uv run --project python rls-doctor diagnose --event PATH_TO_EVENT.json --guide --language ru
```

Для события 1.1 профиль обязателен. Несовпадение ID проекта, отпечатка адреса API,
схемы или ресурса отклоняется до подключения. Это проверка соответствия настроек,
а не криптографическое доказательство маршрутизации API к этой базе. Действительная
Auth-сессия не подтверждает исполняемую роль PostgreSQL или значение auth.uid в
предыдущем запросе. Подтверждённая runtime-роль остаётся неизвестной.

## Удалённый сервер и права

Используйте по возможности отдельную учётную запись. Для чтения каталогов не
нужен SELECT пользовательских строк; доступность конкретных каталогов может быть
ограничена вашим провайдером. Прямые/session endpoints должны поддерживать обычные
транзакции и startup-настройки. Клиентские сертификаты и GSS не поддерживаются.

Вне числового loopback обязателен `sslmode=verify-full`: проверяются CA и имя
сервера. По умолчанию `sslrootcert=system`, для частного CA укажите доверенный файл
в исходном DSN. Его абсолютный путь сохранится в профиле. Пример только с заменителями:

```text
host=YOUR_DATABASE_HOST port=5432 dbname=postgres user=INSPECTOR password=YOUR_PASSWORD sslmode=verify-full sslrootcert=PATH_TO_TRUSTED_CA
```

Путь использует закреплённый Psycopg binary/libpq 18. Локальный числовой loopback
допускает sslmode=disable. Произвольные options/service/hostaddr и multi-host DSN
отклоняются. После DNS фиксируется первый IPv4, либо первый доступный адрес другого
семейства; автоматического перебора отказавших адресов нет. Имя сохраняется для TLS.

## Результат и сохранение

В отчёте есть время/ID диагностики, выбранная роль, права схемы/таблицы/столбцов,
RLS/FORCE, политики, формы условий и упорядоченные следующие действия. Для
события отдельно отображается время запроса. UNKNOWN означает, что видимость
строк или причина исходного запроса не доказаны; конкретные препятствия доступа
при этом показываются отдельно. Никакие политики, данные или пользователи команды
connect/diagnose не изменяют. Воспроизведения запроса нет.

```powershell
uv run --project python rls-doctor diagnose --approve-read-only --format json --output .rls-doctor/reports/database-1.json
```

В этом примере DSN должен быть заранее задан приватно. Существующие файлы отчёта
не перезаписываются. Коды diagnose: 0 PASS, 1 FAIL, 2 UNKNOWN, 3 ошибка выполнения.

Реальные проверки выполнены на изолированном PostgreSQL с TLS и ограниченной ролью,
включая отказы CA/имени/срока сертификата, а также на локальном Supabase с SDK/Auth.
Это не прогон на внешнем облачном проекте пользователя: такой доступ пока не проверен.
