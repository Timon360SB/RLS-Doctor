# Диагностика существующей базы

[English](existing-database.md)

Основной путь продукта — разобрать настройки доступа в вашей существующей
PostgreSQL/Supabase-базе. Для этого не нужны тестовые пользователи, фикстуры,
YAML-сценарий, SDK и пробник роли. Команда читает только каталоги в read-only
транзакции с ограничениями времени запросов/ожидания блокировок. Строки клиентов
не запрашиваются, политики и данные не изменяются.

## Подключение

В копии репозитория установите Python-зависимости:
`uv sync --project python --frozen`. Затем выполните:

```powershell
uv run --project python rls-doctor diagnose public.orders --host YOUR_DATABASE_HOST --role authenticated --language ru
```

Замените таблицу, точный адрес и роль своими значениями. Подтвердите чтение
каталогов указанной базы. Если RLS_DOCTOR_DATABASE_URL не задана через приватное
окружение/менеджер секретов, вставьте строку подключения PostgreSQL в скрытое поле
терминала. Она не сохраняется. Не помещайте настоящий DSN/пароль в аргументы
команд, Git, отчёты или чат. Нужна строка PostgreSQL, а не API-ключ Supabase.
По возможности используйте отдельную учётную запись с ограниченными правами.

Для этой Python-команды не требуются Node.js, pnpm и Docker. Лаборатория и SDK —
отдельные дополнительные возможности.

## Удалённый сервер

Для адреса вне числового loopback обязателен verify-full TLS: проверяются CA
и имя сервера. В DSN можно указать sslrootcert с доверенным CA-файлом оператора
базы; иначе используется sslrootcert=system. При частном CA нужен соответствующий
сертификат, а не ослабленный режим TLS. Путь использует закреплённый Psycopg binary
с libpq 18; клиентские сертификаты/GSS-аутентификация пока не поддерживаются.
Используйте прямой/session endpoint, поддерживающий обычные транзакции и startup-настройки.

Форма строки для скрытого ввода — только образец с заменителями:

```text
host=YOUR_DATABASE_HOST port=5432 dbname=YOUR_DATABASE user=INSPECTOR password=YOUR_PASSWORD sslmode=verify-full sslrootcert=PATH_TO_TRUSTED_CA
```

Для локального числового loopback разрешён sslmode=disable. Обязательны адрес,
порт, база и пользователь. Произвольные options, service, hostaddr и несколько
адресов отклоняются. IP фиксируется после разрешения DNS, TLS сверяет одобренное
имя. Ограничения локального replay не расширяются этим режимом.

## Что покажет результат

RLS/FORCE RLS, роль, владельца/обход правил, права схемы/таблицы/столбцов,
применимость и составление политик. Отсутствие SELECT, USAGE или разрешающей
политики — конкретные факты настройки. Выражения политик и строки таблиц не
собираются, поэтому контекст запроса, поведение условий и видимость строк
остаются неподтверждёнными. UNKNOWN относится к этой runtime-неопределённости;
подтверждённые факты каталогов при этом полезны и показаны отдельно.

Для автоматизации задайте выбранную переменную с DSN приватно:

```powershell
uv run --project python rls-doctor diagnose public.orders --host YOUR_DATABASE_HOST --approve-read-only --format json --output .rls-doctor/reports/database-1.json
```

JSON-режим не задаёт вопросов и требует явного разрешения и переменной с DSN.
Другое имя задаётся через --connection-env NAME. Прежние файлы отчётов сохраняются.

## Что проверено

Команда выполнена на существующих локальных таблицах, включая обнаружение
недостающего GRANT, без подготовки данных, создания пользователей и HTTP-запросов.
Проверки адреса/TLS, отказов и приватности покрыты автотестами. Реальное
подключение к чужой облачной базе и удалённый TLS ещё не проверялись.
