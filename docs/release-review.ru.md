# Независимая проверка кандидата на выпуск

[English](release-review.md)

Пройдите этот список на другом компьютере или в новой среде Windows. Цель —
проверить, сможет ли второй разработчик запустить продукт без прежних настроек
и устных подсказок автора. Повтор на исходном компьютере не подтверждает
установку на чистой системе.

## 1. Подготовка и версия

Установите инструменты из [требований README](../README.ru.md#быстрый-старт):
Git для клонирования, Node.js 22.12+/24, pnpm 11.25.0, uv 0.13.5 и Docker Desktop.
Дождитесь работающего Linux-движка Docker. Windows-запускатель подготавливает
Python 3.12 и находит/загружает Supabase CLI 2.121.0.

Проверяйте ветку/коммит, согласованный с ответственным за выпуск. Для текущей ветки разработки:

```powershell
git clone --branch feat/mvp-foundation https://github.com/Timon360SB/RLS-Doctor.git RLS-Doctor-review
cd RLS-Doctor-review
git rev-parse HEAD
git status --short
node --version
pnpm.cmd --version
uv --version
```

Запишите полный SHA коммита и версии инструментов. В начале не должно быть
изменённых файлов. В PowerShell используйте `pnpm.cmd`; менять общую политику
выполнения скриптов для этой инструкции не требуется. Работайте только с
синтетической локальной средой на доверенном компьютере/в доверенной сети.
Публикация локальных портов описана в [ограничениях](limitations.md).

## 2. Обычный пользовательский путь

```powershell
.\lab.cmd
```

Разрешите подготовку ответом **y**. Выберите **18**: все 18 строк должны
совпасть с ожидаемыми результатами. В намеренных примерах отказа, утечки или
неверных входных данных правильным результатом может быть PASS, FAIL или ERROR.
Смотрите сравнение ожидания и наблюдения. Подробности — в [учебной инструкции](practice-testing.ru.md).

Выйдите пунктом **0**, затем запустите `.\lab.cmd -Language ru` и проверьте
русские меню/отчёты. Не держите две учебные сессии одновременно. Снова выйдите
пунктом **0** и выполните:

```powershell
.\lab.cmd -Stop
.\lab.cmd -Check
Write-Host "Код лаборатории: $LASTEXITCODE"
```

После второй команды ожидается код 0. Так проверяется повторный запуск с
сохранёнными данными. Подготовка создаёт новую пару тестовых пользователей и
переназначает ей восемь строк; старые Auth-пользователи остаются до явного удаления/сброса.

## 3. Установленные пакеты в отдельном приложении

После подготовки зависимостей запускателем:

```powershell
uv run --project python python scripts/task_board_check.py --check
Write-Host "Код приложения: $LASTEXITCODE"
```

Ожидаются PASS для установленного doctor и количества задач **2 / 1 / 0** для
Алисы, Боба и анонимного клиента; все три сценария проходят, общий код 0.
Скрипт собирает/проверяет пакеты, устанавливает их в отдельные окружения,
проверяет нестандартную схему и сверяет сохранённые отчёты с JSON в stdout.
Импорт исходников SDK не заменяет проверку установленных пакетов.
Подробнее — в [руководстве приложения](../examples/task-board/README.ru.md).

По напечатанному пути находятся описанные очищенные отчёты и сводка. При
необходимости передавайте только выбранные файлы, а не всю .rls-doctor:
в ней также находятся локальные зависимости и состояние окружения.

## 4. Завершение и результат

```powershell
uv run --project python python scripts/task_board_check.py --stop
.\lab.cmd -Stop
git status --short
```

Обе среды должны остановиться с сохранением данных, отслеживаемые исходники —
остаться без изменений. Заполните сводку самостоятельно; не отмечайте то, что не запускали.

```text
SHA коммита:
Чистая среда Windows: да / нет
Версия Windows:
Версии Node / pnpm / uv:
Английская лаборатория: совпали все 18 / ошибка в пункте ... / не проверял
Русское меню и отчёт: проверил / не проверял
Остановка и запуск с сохранением данных: прошли / ошибка / не проверял
Установленное приложение: Алиса 2, Боб 1, аноним 0 / другое / не проверял
Doctor и экспорт отчётов: прошли / ошибка / не проверял
Остановка обеих сред: прошла / ошибка / не проверял
Отслеживаемые файлы не изменились: да / нет
Проблемы: шаг, ожидалось/получено, диагностический код
Вывод проверяющего: готово / нужны исправления / проверка не завершена
```

Не включайте пароли, токены, ключи, сырой вывод Supabase status/запуска,
дампы переменных окружения и рабочие данные. Строка соавторства не заменяет
независимое ревью: через обычный процесс ревью укажите, кто реально выполнил проверку.

## Архивы проверенной сборки из CI

В прогонах с шагом сохранения preview-архивов появляются артефакты
`preview-<коммит>-node-<версия>-py-<версия>-attempt-<номер>`, хранящиеся семь дней.
Откройте нужный запуск GitHub Actions и скачайте его артефакт, войдя в GitHub.
После распаковки должны быть ровно три архива пакетов, SHA256SUMS и manifest.json.
До использования проверьте совпадение manifest.git_head с кандидатом и
контрольных сумм файлов с SHA256SUMS.

Это preview-артефакты конкретного запуска. Успешный CI прежнего коммита не
подтверждает последующие изменения. Скачивание preview, независимая проверка
и публичный выпуск — отдельные шаги.
