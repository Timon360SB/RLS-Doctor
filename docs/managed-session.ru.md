# Управляемая локальная сессия

Команда session сама получает ключи работающего локального Supabase через CLI,
сверяет адрес API и разрешённый порт БД с одобренной конфигурацией. Ключи не
печатаются и не записываются в файлы; копировать их в команды не требуется.

1. Запустите Docker и локальный Supabase своего одноразового тестового проекта.
2. Подготовьте конфигурацию через `rls-doctor init --interactive --language ru`.
   Проверьте адрес и явно подтвердите, что это локальная тестовая среда.
3. Из папки репозитория RLS Doctor выполните:

```powershell
uv run --project python rls-doctor session --config путь/к/rls-doctor.toml --workdir путь/к/локальному-проекту --language ru
```

Подставьте свои пути. Папка workdir должна содержать `supabase/config.toml`.
Сценарий по умолчанию — `documents.yaml` рядом с конфигурацией; другой можно
выбрать параметром `--scenario`. Supabase CLI должен быть установлен. Версия,
подготовленная Windows-демо в кэше npm, также находится автоматически.

Для анонимного сценария токен пользователя не нужен. Для авторизованного сессия
использует уже заданный локальный тестовый токен. Если его нет, предложит создать
одного синтетического Auth-пользователя. Пароль генерируется автоматически,
не показывается и не записывается в конфигурацию. Без согласия регистрации не будет.
В режиме без меню `--run` создание запрещено, пока явно не добавлен
`--create-test-user`. Это подготовка локальной Auth, а не операция записи replay.

В меню выберите выполнение сценария или анализ таблицы. Проверка не добавляет
строки приложения, не меняет владельцев, политики или схему. Новый Auth-пользователь
не владеет существующими строками и остаётся в локальной среде до удаления или
её намеренного сброса. Автоматического удаления нет. Если локальная Auth требует
подтверждения почты, регистрация может не вернуть сессию; настройки не меняются.

Без доверенной проверки исполняемой роли результат replay может быть UNKNOWN:
проверенная подпись токена не доказывает роль PostgreSQL. Инспектор также не
подтверждает поведение запроса по одним каталогам. Ожидания сценария должны
соответствовать отдельно подготовленным синтетическим данным.

При выходе секреты не переходят в родительский терминал, прежнее окружение
процесса восстанавливается. Docker остаётся запущенным. Пункт выхода завершает
меню с кодом 0, но не означает, что все проверки прошли. Режим `--run` сохраняет
код результата: PASS 0, FAIL 1, UNKNOWN 2, ERROR 3. После редактирования настроек
перезапустите сессию. Полный список ошибок — в [английской версии](managed-session.md).


## JSON для автоматических проверок

Добавьте `--run --format json`: сессия выведет один JSON-объект без текста
подготовки и меню. Коды сохраняются: PASS 0, FAIL 1, UNKNOWN 2, ERROR 3.
Язык интерфейса не меняет машинный формат. `--format json` без `--run`
отклоняется с SESSION_JSON_MODE / 3. Прерывание одноразового запуска —
SESSION_CANCELLED / ERROR / 3, а не успешное завершение проверки.
В этом режиме регистрация по-прежнему требует явного `--create-test-user`.


## Связь с событием SDK

Добавьте `--event путь/к/event.json` к команде session. Файл проверяется по общей
схеме до загрузки ключей. Если ресурс события отличается от ресурса сценария,
запуск отклоняется с EVENT_MISMATCH. Фильтры и тестовые значения по-прежнему
задаются сценарием: обезличенное событие не восстанавливает исходный запрос.
Роль, подтверждённая локальным пробником, относится только к локальному тесту,
а не к личности исходного запроса. JSON сохраняет существующее поле event_id.

Мастер init повторяет только неверный вопрос. В поле числа строк можно ввести
`пропустить`/`skip`, чтобы не сравнивать количество. Для ожидаемого HTTP-отказа
это значение предлагается по умолчанию; код ответа проверяется отдельно.


Событие v1 не сохраняет выбранную схему/profile. Совпадение имени ресурса
связывает отчёт, но не подтверждает исходную схему; схема replay задаётся в YAML.
[Отдельный пример с задачами](../examples/task-board/README.ru.md) проверяет
нестандартную схему на настоящем API через установленные пакеты.


## Сохранить отчёт без перенаправления PowerShell

Добавьте `--run --output .rls-doctor/reports/session-1.json`. CLI запишет JSON
напрямую в UTF-8; консольный вывод по-прежнему определяется --format. При
успешном сохранении коды PASS/FAIL/UNKNOWN/ERROR не меняются. Для интерактивного
меню --output без --run отклоняется с SESSION_OUTPUT_MODE. Существующий файл
не перезаписывается: выберите новое имя. Проверка существования выполняется
до загрузки ключей. Ошибка сохранения возвращает ERROR / 3. Лимит файла — 1 МиБ;
для атомарной записи нужна файловая система с жёсткими ссылками. На Windows
права доступа наследуются от папки назначения.
